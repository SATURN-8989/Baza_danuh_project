# Этап 1. Сбор и анализ требований — Учет в музыкальной школе

## 1. Описание предметной области и ключевые процессы

Ученики занимаются у преподавателей по предметам в классах, расписание не должно конфликтовать. В веб-интерфейсе администратора важно видеть конфликты в расписании, посещаемость и оплату занятий.

### Ключевые процессы

| Процесс | Шаги | Что меняется в данных |
| :--- | :--- | :--- |
| **Регистрация ученика** | Администратор вносит данные нового ученика -> создается карточка | Создается запись в «Пользователь», присваивается ID |
| **Назначение расписания** | Администратор выбирает предмет, преподавателя, класс, день и время -> система проверяет накладки | Создается запись в «Расписание», статус «активно» |
| **Фиксация посещаемости** | Преподаватель или администратор отмечают галочкой факт присутствия ученика на уроке | Обновляется запись в «Журнал занятий» и проставляется статус (был, не был, опоздал) |
| **Оплаты** | Родитель вносит деньги -> администратор фиксирует перевод и сумму | Создается запись в «Платежи», обновляется баланс |
| **Поиск свободного класса** | Администратор ищет свободную аудиторию в конкретное время | Чтение данных |

## 2. Ограничения

| Тип | Ограничения | Источник |
| :--- | :--- | :--- |
| **Структурное** | У каждого урока в расписании есть ученик, преподаватель и класс | Физическая реальность |
| **Структурное** | У каждой записи в журнале посещаемости есть ссылка на конкретный урок | Логика процесса |
| **Структурное** | Если должность сотрудника (преподавателя), то ему указывают его музыкальную специальность | Логика процесса |
| **Бизнес-правило** | Один преподаватель не может вести два разных занятия в одно и то же время | Физическая реальность |
| **Бизнес-правило** | В одном учебном классе не может проводиться больше одного занятия одновременно | Физическая реальность |
| **Бизнес-правило** | Ученик не может быть записан на 2 занятия сразу | Физическая реальность |
| **Техническое** | Номер телефона ученика уникален | Техническое |
| **Техническое** | Номер договора (ID ученика) уникален | Техническое |
| **Техническое** | Табельный номер сотрудника (администратора/учителя) уникален | Техническое |

## 3. Роли пользователей

### Роль «Пользователь» (Ученик / Родитель)

| Действия | Входные данные | Результат | Ограничения |
| :--- | :--- | :--- | :--- |
| **Просмотр календаря** | ID пользователя | Личное расписание | Только чтение |
| **Контроль баланса** | ID пользователя | История транзакций | Только свои данные |
| **Просмотр ДЗ** | ID пользователя и урока | Текст задания | Только чтение |
| **Отмена урока** | ID урока и причина | Запрос на отмену | За 12 часов до урока |
| **Запись на мастер-класс** | ID пользователя и события | Добавление в группу | Только при плюсе |

### Роль «Администратор»

| Действия | Входные данные | Результат | Ограничения |
| :--- | :--- | :--- | :--- |
| **Регистрация** | ФИО, телефон | Новый профиль | Уникальный телефон |
| **Новый урок** | Преподаватель, класс, время | Урок в сетке | Проверка накладок |
| **Оплата** | ID ученика, сумма | Баланс + | Сумма > 0 |
| **Заморозка** | ID ученика, даты | Стоп списаний | До 14 дней |
| **Экзамен** | Дата, класс, комиссия | Событие в сетке | Блокирует класс |
| **Возврат** | ID ученика, сумма | Баланс - | Только при плюсе |
| **Ремонт** | ID класса, период | Статус «Ремонт» | Перенос уроков |
| **Отчеты** | Период | Готовый отчет | Только для админа |

### Роль «Преподаватель»

| Действия | Входные данные | Результат | Ограничения |
| :--- | :--- | :--- | :--- |
| **Расписание** | ID преподавателя | Свои уроки | Только чтение |
| **Журнал и ДЗ** | ID урока, явка, ДЗ | Урок закрыт | Запись за 24 часа |
| **Репертуар** | ID ученика, песня | Прогресс ученика | Только свои ученики |
| **Перенос** | ID урока, время | Запрос админу | За 2 часа до урока |
| **Аттестация** | ID ученика, балл | Архив оценок | Только в сессию |

## 4. Бизнес-правила

| № | Бизнес-правило | Категория | Где реализуется |
| :--- | :--- | :--- | :--- |
| **Б1** | Один преподаватель не может вести два занятия одновременно | Ограничение состояния | Логика приложения / Триггер |
| **Б2** | В одном учебном классе не могут проходить два занятия сразу | Ограничение состояния | Логика приложения |
| **Б3** | Баланс пользователя не может уходить в минус более чем на 2 урока | Ограничение значения | Триггер на баланс |
| **Б4** | Номер телефона пользователя должен быть уникальным в системе | Ограничение уникальности | Ограничение на уровне СУБД (`UNIQUE`) |
| **Б5** | При пропуске без уважительной причины ставится статус «не был» и списывается оплата | Ограничение значения | Хранимая процедура при закрытии урока |
